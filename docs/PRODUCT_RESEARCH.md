# Pearl Pocket 产品改进与 Pearl Hub 参考

研究日期：2026-10-07。依据 [Pearl Hub 的 App Store 功能与更新记录](https://apps.apple.com/us/app/pearl-hub-prl-wallet-pools/id6777132941)、[开发者网站](https://prl-hub.vercel.app)和 [HeroMiners Pearl](https://pearl.herominers.com)。以下是功能参考与本应用的实现决策，不代表对另一产品进行安全审计，也不复用其源码、商标或素材。

## 已落地到 0.4.0

| 方向 | 值得学习的产品设计 | Pearl Pocket 本轮实现 |
| --- | --- | --- |
| 日常收发 | 地址簿与二维码减少重复输入 | 本机联系人新增、编辑、删除、选择及完整地址校验；相机与本机图片扫码预填 |
| 收款请求 | 金额和地址一起呈现 | 默认兼容纯地址二维码，可另外生成带 PRL 金额的 Pearl Pocket 收款请求 |
| 交易核对 | 确认前展示费用，结果不确定时避免重复付款 | 保留已有精确手续费预览与原签名交易重发；增加本地址净变化、确认数、交易 ID 复制和浏览器入口 |
| 行情跟踪 | 将提醒融入行情页 | PRL/USDT 高于或低于目标价的一次性本机通知，失效行情不触发，已触发状态先持久化 |
| 矿业工具 | 公开矿池统计与成本计算 | HeroMiners 总算力、全网占比、矿工和工作器、费率、高度及接收时间；包含电费、矿池费、租金的收益情景计算 |
| 数据可信度 | 显示更新时间，区分实时与过期 | 延续行情时间与失效提示；矿池明确标注本机接收时间，刷新失败保留旧值并显示错误 |

从参考产品最值得学的是：围绕用户的日常任务组织功能，把价格来源、数据时效和确认步骤直接呈现出来。不要把矿池收益、币价或手续费的估计值做成没有来源的精确数字。

## 本轮实现边界

扫码完全在本机进行。相机仅在用户进入扫码时申请权限；也可通过系统文件选择器读取单张图片，无相册全量读取权限。扫码结果只填入地址和金额，不预览或发送交易。拒绝错误网络地址、网页链接、未知参数、重复参数和超出 grain 精度的金额。`pearl:<address>?amount=<PRL>` 是 **Pearl Pocket 自定义的收款请求格式**，没有把它宣称为 Pearl 协议或 Oyster 的通用标准。纯地址二维码仍是默认选项。

地址簿与提醒只保存公开信息，位于应用私有存储，随应用备份策略禁用云备份及设备迁移。不访问种子、私钥、Keystore 钱包密钥或签名接口。卸载或清空数据会删除这些公开配置；现阶段没有联系人导出或同步。

价格提醒使用 BigONE PRL/USDT 报价；前台随新报价检查，后台使用 [Android JobScheduler 的周期任务](https://developer.android.com/reference/android/app/job/JobInfo.Builder#setPeriodic(long))，最低周期 15 分钟。省电、网络、系统调度和强制停止会延迟检查，**不是关闭应用后的即时服务器推送**。每条提醒触发一次；价格超过 120 秒失效或系统通知关闭时不触发。只有保存提醒时才申请 [Android 通知权限](https://developer.android.com/develop/ui/views/notifications/notification-permission)。后台服务只查询公开行情，不读取钱包地址。

后台任务声明普通权限 `ACCESS_NETWORK_STATE`，满足 [Android 14 的 JobScheduler 网络约束要求](https://developer.android.com/about/versions/14/behavior-changes-14#jobscheduler)。提醒页显示后台检查是否已安排；读取网络状态不需要用户运行时授权。

HeroMiners `/api/stats` 的 `hashrate` 是内部份额速率，`totalRealHashrate` 才是包含普通与 Solo 模式的实际矿池算力；与 `network.networkHashps` 比较使用后者。币种必须为 `pearl / PRL`，单位必须为 100,000,000 grain。矿池人数也包含普通及 Solo。API 没有经验证的数据生成时间，本应用只声称本机接收时间。公开矿池查询不带本钱包地址。

收益计算输入费前 PRL/天、CNY/PRL、瓦数、电价、矿池费率、日租金。日收入 = 预估币量 × (1 − 矿池费率) × 币价；电费 = 功耗 / 1000 × 24 × 电价；净收益 = 日收入 − 电费 − 租金。30/90 天假设输入保持不变，盈亏平衡币价 = (电费 + 租金) / 扣矿池费后的日币量。无产出时不显示虚构的盈亏平衡币价。全部使用十进制运算；没有根据当前难度承诺未来产出。

## 后续迭代顺序

三个方向持续推进，每轮都包含钱包、行情、矿业改进。

| 优先级 | 功能 | 先满足的条件 |
| --- | --- | --- |
| 下一轮 | 多钱包与独立钱包切换 | 每个钱包独立密文、备份状态、未确认交易，切换不能串用 UTXO 或联系人收款地址 |
| 下一轮 | 矿工地址监控、工作器离线提示、多矿池比较 | 分别核对各矿池 API 单位、更新时间、查询权限与错误语义，明确发送的是公开地址 |
| 下一轮 | 提醒编辑/重新启用、更多图表周期、持仓价值变动 | 历史报价一致性、通知去重、数据过期规则，提供可理解的后台检查状态 |
| 下一轮 | 联系人导出、带金额二维码分享为图片、交易筛选 | 用户主动选择文件、校验导入格式、避免把备份助记词和公开联系人混用 |
| 专项开发 | 官方 Oyster 的完整恢复与 XMSS/P2MR 签名 | 先验证官方恢复格式、地址扫描、XMSS 状态持久化和签名索引，避免状态重复造成密钥风险 |
| 专项开发 | 桌面组件、即时后台推送 | 定义可见信息与隐私选择；即时推送需额外服务、订阅和设备标识，不能等同本机轮询 |
| 专项开发 | 交易所买卖或兑换 | 独立 API 密钥存储、交易权限、订单确认、提现费用及故障处理；不混入本机私钥签名流程 |

暂时优先提高日常使用质量，不用添加未经验证的协议支持来扩大功能表。当前固定 BIP86 钱包仍不等同于 Oyster 全账户恢复；安全与恢复能力需要按真实实现描述。
