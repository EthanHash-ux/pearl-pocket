# 掌珠钱包：钱包优先的产品方向

掌珠钱包的主线是让用户安全地持有、收取、支付和记录 Pearl 资产。矿池查询与跨链报价是已有的辅助工具，后续投入优先给钱包。已发布版本和开发中的能力以 README 与各版发布说明为准；下列未完成事项不属于现有功能。

## 第一阶段：多个独立钱包

日常付款、长期储蓄和店铺收款可以分别创建或导入钱包，设置名称并切换。每个钱包分别保存助记词、钱包密码、设备密钥、备份状态和待发送交易。观察地址仍只读，不冒充手机签名钱包。转账确认展示付款钱包和完整地址。

0.9.0 实现这一步，支持最多 10 个手机钱包。旧版的钱包保留原文件和加密格式，不移动或覆盖。不同钱包的转账分别签名与处理，切换不会移动资金。操作中的设备验证和签名结束前不允许切换。

## 第二阶段：收款请求与日常对账

现有带金额二维码、分享图片、交易备注和 CSV 可以支持个人或小商家收款。下一步增加本机订单号、用途、应收金额、生成时间，以及待支付 / 待确认 / 已核对记录。订单绑定实际链上交易 ID，并使用用户选定的确认要求，付款截图不能代替链上核验。

固定单地址不能唯一识别多个同额订单，所以先由用户选择并绑定交易，防止一笔到账重复核销。自动生成不同收款地址需要同步开发地址扫描、恢复和找零管理。

## 第三阶段：备份与换机

强化每个钱包的备份进度、恢复演练和兼容性说明；换机向导允许逐个恢复并核对原地址。联系人、钱包名称、观察地址和公开偏好可单独导出。公开配置不能包含助记词、钱包密码或设备密文，也不能代替助记词备份。

当前设备 Keystore 密文不能复制到另一台手机后直接解锁。加密助记词备份若要支持，需要独立设计可移植格式、口令强度与恢复验证，再纳入发布测试。

## 第四阶段：资产与交易记录

汇总用户选择的钱包与观察地址，按地址去重；没有查询成功的账户显示未知与时间，不算作零余额。分别展示已确认、待确认和跨链中的资产，避免重复累计。

增加收支分类、月度报表和项目 / 客户记录。历史法币金额使用交易当时的参考价格并记录来源，不能用今天的价格冒充过去的收入。进一步完善交易失败说明、费用展示和同一交易重试流程。

## 后续研究

新派生收款地址、离线签名、硬件钱包和多人签名值得研究，但必须逐项验证 Pearl 协议、恢复扫描与外部设备兼容性。比特币钱包已有类似流程可作体验参考，不能据此宣称 Pearl Pocket 已兼容这些格式。参考 [BlueWallet 的观察钱包流程](https://bluewallet.io/watch-only/) 与 [离线钱包说明](https://bluewallet.io/docs/offline-cold-wallet/)。

每阶段先完成真实钱包操作和升级测试，再扩大功能范围。当前依然是开发测试版；真机验证和独立安全审计是面向更大规模用户前的工作。
